Home library app: the plan in short

2026-10-13 · short version for Miro · full plan (separate password)

Summary Key decisions Phases Risks Open questions

Summary

We build one small Python web app, not a native app. It sits next to the existing hl pipeline and runs on battlebox. Every device reaches it privately through Tailscale.

  • The phones install it to the home screen and send photos.
  • The iPad and laptop use it in the browser to review the results.

There is no Mac, no Apple account and no MacinCloud anywhere in the plan. All four council seats (Opus, Fable, Sol, Astra) agreed on this shape.

Key decisions

  • Stack: FastAPI with Jinja templates and HTMX, SQLite, and one worker process that runs hl on each new photo.
  • Host: battlebox in WSL2, with HTTPS and login provided by Tailscale. Exactly two family logins are allowed.
  • Data: an uploaded photo produces observations, which are evidence only. A book exists once a person approves it, with a state and a location.
  • Ways in: shelf, cover and barcode photos. Barcodes are decoded on the server. Covers and barcodes are both in the first version.
  • Upload: from the open page, with retries. The originals stay in the camera roll as a backup.
  • Fallback: an Expo Android app, only if taking photos in the browser fails.

Phases

0 · Tests before building 2–3 evenings
  • Does battlebox run things unattended?
  • Do the phones upload full-size photos from the browser?
  • Do cover and barcode photos work?
  • Is Grist good enough for review, in a one-evening test?
1 · Back end L
  • The upload endpoint, the job queue and the worker.
  • The catalog database.
  • New hl cover and hl barcode commands.
  • A JSON API and hl catalog commands for agents.
2 · Web pages L
  • A capture page for the phones.
  • A review page for the iPad, built for the keyboard: photo and tile beside the fields, with the catalogue candidates.
  • Search, and a locations page.
3 · Running it M
  • The app starts by itself at boot.
  • Nightly backups to Battlebook, with one restore tested.
  • A CSV and JSON export.
4 · Only if needed: Expo Android app
  • Installed from a link, with no Play Store account.
  • It uses the same upload endpoint.

Risks

  • high The browser may shrink photos, and the tiles need full size. Phase 0 tests this first.
  • high WSL on battlebox may not stay up. Phase 0 checks it, and the app is a single folder that can move.
  • med The Codex or Pi login may expire. Failures show on a status page; nothing fails silently.

Open questions

The same numbers as in the full plan. Answer with a number and "default" or "alt".

  1. Always-on host?

    default battlebox in WSL2. alt A small Linux box.

  2. May photos leave the house for backup?

    default No. alt An encrypted backup to Drive.

  3. Tailscale on your wife's phone and the iPad?

    default Yes. alt No: home Wi-Fi only.

  4. Do the one-evening Grist test?

    default Yes, time-boxed. alt Skip it.

  5. A cover photo for every book?

    default Only for books the shelf photo couldn't identify. alt For all books.

  6. A book that leaves the house?

    default Keep it as "Gone". alt Delete it.

  7. Location names?

    default "Shelf A1" and "Box 1" style. alt Free names.

  8. Second read?

    default Muse Spark, as built. alt A second Sol session.

  9. Use the work Apple account?

    default No, none is needed. alt A personal account if a native iPad app is ever wanted.
